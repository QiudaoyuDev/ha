## 悦都全屋 Home Assistant 项目分析
- 项目：深圳保利悦都两室一厅智能家居中控，基于 HA 原生 Lovelace（yaml mode），主终端 iPhone。
- 架构分层：表现层(dashboard-v2 8 view) / 语义层(templates/yuedu_ui.yaml 中文态隔离) / 控制层(scripts+homekit桥接) / 集成层(xiaomi_home,haier,hacs) / 基础设施(Docker host网络)。
- 关键发现：README 声称"不依赖 HACS"，但 v2 实际用了 Mushroom + Bubble Card（www/community 下）。文档与实现矛盾，需修正。
- 已产出报告：`docs/悦都全屋_项目概述与UI演进报告_20260731.md`（架构/模块/依赖/同类对比/UI重构方向）。
- UI 演进重点（用户要求偏 UI）：统一卡片语言+设计令牌、Bubble Pop-up 就地控制、Sections 视图、Floorplan Card(SVG) 替代 picture-elements、Kiosk/墙屏、对接 HA MCP 做 AI 中枢。
- 同类项目对比：mushroom, bubble-card, ha-fusion(Hearth), Dwains Dashboard, card-mod, Floorplan Card, Tile Card(原生), HA MCP。

## deploy/homeassistant 才是生产配置（更正）
- `deploy/homeassistant` 是真正在跑的生产配置，仪表盘为 **v4**，比 `homeassistant-yuedu`(v2 样例) 先进很多。用户要求只看 deploy 目录。
- v4 配置要点：原生 `sections` 视图 + `theme: 悦都暖石`(themes/yuedu-warm.yaml，固定白昼暖色、无 dark mode) + Mushroom 全系卡 + Bubble Card pop-up(hash 锚点) + `conditional` 离线收起控件。
- 语义层 `templates/yuedu_ui.yaml` 输出干净的 `sensor.yue_du_*` 中文态（门锁/摄像机/空调/循环扇/洗衣机/全屋聚合离线计数），仪表盘只引用语义实体。
- 部署方式关键：Docker host 网络；**Windows + Docker Desktop 上 HomeKit mDNS 需旁路**——`scripts/homekit_mdns_advertiser.py` 用 docker exec 读容器内 HAP 记录、宿主机 zeroconf 重公告(zeroconf==0.150.0)，install 脚本装为计划任务并开防火墙 21063/5353(Private)；Python 路径硬编码 C:\Users\lzx10\... 可移植性差。
- `source/ha_xiaomi_home` 为小米集成完整源码(含 install.sh/tests/CLAUDE.md)，便于内网安装。
- 依赖版本：HA :stable(未锁)、hacs 2.0.5、xiaomi_home v0.4.7、haier 1.2.0、Mushroom/Bubble Card 打包 JS 无版本文件。
- 已产出报告：`docs/悦都全屋_deploy配置与部署分析_20260731.md`（配置方法/部署方式/依赖/风险）。
- 改进建议：锁 HA 镜像 tag、固定前端卡版本、去硬编码 Python 路径、条件化 mDNS 旁路、排除 db/log/secrets 入库、UI 下一步 Floorplan Card(SVG)/Kiosk/HA MCP。
