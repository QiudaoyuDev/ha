## 排障：Windows 访问不到 WSL 内 HA（已解决 2026-07-31）
- 现象：WSL 内 `curl localhost:8123`=200、监听正常；但 Windows 侧 `Test-NetConnection localhost/10.12.50.103/192.168.196.135` 全部 False，浏览器打不开。
- 环境：Windows 25H2 Build 26200，`.wslconfig` 已是 `[wsl2] networkingMode=Mirrored / firewall=false / hostAddressLoopback=true`。会话无管理员权限，无法加防火墙入站规则。
- 根因：`docker-compose.yml` 用 `network_mode: host`，在 WSL2 镜像网络模式下 host 模式容器端口**不发布到 Windows 宿主**，且防火墙拦截 → 连不上。
- 修复：prod 的 `docker-compose.yml` 改回桥接发布端口（`ports: - "8123:8123"` 替代 `network_mode: host`），`docker compose up -d` 重建容器。
- 验证：容器 PORTS=`0.0.0.0:8123->8123/tcp,[::]:8123->8123/tcp`；Windows `Test-NetConnection localhost 8123` → TcpTestSucceeded=True；`http://127.0.0.1:8123` → 200（UI 正常）。`http://localhost:8123` 也可（个别浏览器 localhost 优先走 ::1 会慢，建议用 127.0.0.1）。
- 待办：① 同网段设备访问 `10.12.50.103:8123` 现在应可用；② `homekit.yaml` 的 `advertise_ip: 192.168.1.5` 需改 `10.12.50.103`（否则 iPhone 家庭 App 配不对 HomeKit）；③ 首登后 HACS 装 card-mod + Floorplan Card。
- 经验：WSL 内执行含 `$(...)`/`$var` 的 bash 命令时，PowerShell 双引号会先展开 → 报错 `$c not recognized`；应改用单引号包裹 bash 命令（`wsl -e bash -lc '...'`）。

## ⚠️ floorplan-card v1.1.5 不兼容导致 UI 倒退（2026-07-31 修正）
- 用户反馈升级后 2.5D 户型图消失。根因：`ExperienceLovelace/ha-floorplan` v1.x 是重写版，用 `rules:` 模型（`image:` 背景 + `svg:` 叠加 + `rules:` 实体映射），**不支持**旧版 `<ha-state-icon>`/`on-tap` 写法（核对 floorplan-card.js：ha-state-icon=0、on-tap=0、rules=16、image=41）。
- 我之前写的 `yuedu-home.svg`（ha-state-icon + `<image>` 背景）在 v1.1.5 下整体渲染失败，连背景图都不显示 → 首页/房间/地图页都看不到户型图。
- 处理：5 处 floorplan-card 全部回退为 `picture-elements` + `yuedu-home-2p5d.png` 背景（首页3标记+3房间图标+地图5标记）。校验通过，2.5D 恢复。
- 教训：用自定义卡前务必核对目标版本的配置模型（尤其重写版），不要假设旧语法兼容；无法浏览器实测时，优先用已知可靠的 picture-elements，floorplan-card 需按 rules 模型重写并实测后再切。
- 资源 `www/community/floorplan-card/` 与 lovelace_resources 注册暂保留，待 rules 模型正确实现后启用。
