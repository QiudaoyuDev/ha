# 悦都全屋 Home Assistant：天气、家庭日历与万年历集成实施方案

> 适用仓库：`QiudaoyuDev/ha`  
> 编制日期：2026-07-31  
> 目标：在不破坏现有 Dashboard v5、2.5D 户型图、Mushroom/Bubble 交互体系的前提下，引入天气、家庭日程、农历/节气/节日，并同时适配手机端与墙屏端。

---

## 1. 最终选型结论

### 1.1 推荐组合

| 能力 | 推荐组件 | 角色 | 是否核心依赖 |
|---|---|---|---|
| 天气数据源 | Home Assistant 官方 `Open-Meteo` 集成 | 生成统一 `weather.*` 实体，提供当前、逐小时、逐日预报 | 是 |
| 首页天气卡 | `pkissling/clock-weather-card` | 日期、时间、当前天气、未来天气趋势 | 是 |
| 家庭日程数据源 | 官方 `Local Calendar`，后续可接 CalDAV/Google Calendar | 生成 `calendar.*` 实体 | 是 |
| 日程展示卡 | `alexpfau/calendar-card-pro` | 未来事件、多个日历、天气联动、移动端紧凑展示 | 是 |
| 农历/万年历 | `knoop7/ha_laohuangli` | 农历、节气、节日、宜忌、时辰等本地计算 | 可选增强 |
| 原生降级卡 | HA 官方 `weather-forecast`、`calendar` | 第三方卡片异常时快速回退 | 必须保留方案 |

### 1.2 不采用的组合

1. 不同时安装并使用 `Calendar Card Pro` 与 `Atomic Calendar Revive`。两者功能重叠，维护两套配置没有收益。
2. 不在首页直接放完整 `custom:almanac-card`。完整黄历信息密度过高，会破坏当前“状态先于控制”的首页层级。
3. 不为天气单独引入 iframe、ha-fusion 页面或外部天气网页。
4. 不把工作日历、私人事件描述、地点直接展示到公共墙屏。
5. 不启用老黄历插件的 AI 预测能力，不配置任何第三方 AI API Key。

## 2. 当前项目基础与约束

当前生产配置位于：

```text
deploy/homeassistant/
├── docker-compose.yml
└── config/
    ├── configuration.yaml
    ├── dashboards/
    │   ├── dashboard-v2.yaml
    │   └── dashboard-wall.yaml
    ├── templates/
    │   └── yuedu_ui.yaml
    ├── themes/
    └── www/
```

当前项目特征：

- Home Assistant 使用 `stable` 镜像。
- 手机端主面板是 `dashboard-v2.yaml`，采用 Sections 布局。
- 墙屏面板是 `dashboard-wall.yaml`。
- 已使用 Mushroom、Bubble Card、card-mod、button-card。
- `templates/yuedu_ui.yaml` 是语义层，Dashboard 不应直接处理 `unknown`、`unavailable`。
- HACS 已存在，因此新增前端卡片应继续由 HACS 管理，不把下载源码目录当运行目录。

本次集成必须延续以下原则：

```text
外部数据源 → HA 实体 → 悦都语义层 → Dashboard 卡片
```

## 3. 开源组件调研与取舍

### 3.1 天气卡

#### A. Clock Weather Card：主选

仓库：`pkissling/clock-weather-card`

优势：

- HACS 默认库可安装。
- 同时显示时间、日期、当前天气和未来趋势。
- 支持 `zh-CN`、24 小时制、逐日/逐小时模式。
- 支持湿度、体感温度、AQI 等可选实体。
- 视觉风格接近 iOS，适合当前 iPhone 与墙屏使用场景。
- 2026 年仍有活跃版本发布。

适合本项目的原因：

- 首页本来缺少“今天是什么时间、什么天气”的公共信息。
- 一张卡同时承担时钟和天气，不需要再引入单独时钟卡。
- 与现有暖雾主题容易融合。

#### B. HA 原生 Weather Forecast Card：降级方案

优势：

- 无 HACS 依赖。
- 支持 daily、hourly、twice_daily。
- HA 官方持续维护。

用途：

- 第三方资源未加载时的应急回退。
- 用于开发阶段验证 `weather.yuedu_home` 实体本身是否正常。

#### C. Weather Forecast Card（troinine）：暂不作为主卡

仓库：`troinine/ha-weather-forecast-card`

优势：

- 可切换逐小时/逐日。
- 有图表、降水、风向、日出日落等详细能力。

不作为本期主卡的原因：

- 首页信息密度偏高。
- 与 `clock-weather-card` 功能重叠。
- 更适合作为未来独立“天气详情”页面升级项。

---

### 3.2 日历卡

#### A. Calendar Card Pro：主选

仓库：`alexpfau/calendar-card-pro`

优势：

- 活跃维护，支持较新的 Home Assistant。
- 多日历、事件过滤、重复事件过滤、紧凑/展开模式。
- 支持日期列天气和事件时段天气。
- 支持主题变量与 card-mod。
- 性能设计比 button-card 拼装日历更合理。
- 适合家庭共享日历和墙屏的未来事项列表。

#### B. Atomic Calendar Revive：成熟备选

仓库：`totaldebug/atomic-calendar-revive`

优势：

- 历史成熟、配置能力丰富。
- 事件列表和日历模式均支持。
- 活跃维护。

不选原因：

- 本项目更需要现代、紧凑、移动优先的事件列表。
- Calendar Card Pro 已能直接与天气实体联动。
- 两者并存会增加前端资源和配置维护成本。

#### C. HA 原生 Calendar Card：降级方案

优势：

- 无第三方资源。
- 支持月、日、未来 7 天列表。
- 可直接验证 `calendar.*` 数据源。

---

### 3.3 万年历/农历

#### Chinese Almanac for Home Assistant：推荐为可选增强

仓库：`knoop7/ha_laohuangli`

能力：

- 公历日期、农历、星期、周数。
- 传统节日、节气、季节。
- 宜、忌、吉神、凶煞、时辰等完整黄历信息。
- 自带 `custom:almanac-card`。
- 前端卡 JS 由集成自动注册，无需在 Lovelace `resources:` 重复声明。
- 主要历法数据在本地计算。

风险与边界：

- 它是第三方自定义集成，不应成为首页、设备控制或核心自动化的硬依赖。
- 插件包含生日、事件、通知、AI 预测等扩展，本项目只启用基础历法。
- AI 功能必须关闭；不得把 API Key 写入仓库。
- 完整黄历只放独立详情页，首页只展示“农历 + 节气/节日”摘要。

## 5. 数据层实施

### 5.1 配置 Open-Meteo

在 Home Assistant UI 中执行：

```text
设置 → 设备与服务 → 添加集成 → Open-Meteo
```

选择 `Home` Zone。

完成后，将生成的天气实体统一重命名为：

```text
weather.yuedu_home
```

要求：

- 必须能提供 daily forecast。
- 最好同时支持 hourly forecast。
- 不在 YAML 中硬编码经纬度。
- 家庭地点由 Home Assistant 的 Home Zone 管理。

验收：

```text
开发者工具 → 状态 → weather.yuedu_home
```

确认：

- 状态不是 `unknown` 或 `unavailable`。
- 有 temperature、humidity、wind_speed 等可用属性。
- 调用 `weather.get_forecasts` 能返回 daily 和 hourly 中至少一种。

---

### 5.2 配置家庭日历

第一阶段先创建两个官方 Local Calendar：

```text
calendar.yuedu_family
calendar.yuedu_birthdays
```

建议名称：

```text
悦都家庭
悦都生日纪念日
```

数据边界：

- `yuedu_family`：家庭出行、物业、维修、缴费、家务等。
- `yuedu_birthdays`：生日、结婚纪念日等。
- 不把个人工作日历直接放墙屏。

第二阶段可选：

- 接入 CalDAV、Google Calendar 或只读 ICS。
- 继续映射到单独 `calendar.*` 实体。
- Calendar Card Pro 只选择允许展示的实体。

---

### 5.3 安装 Chinese Almanac

HACS 自定义仓库：

```text
https://github.com/knoop7/ha_laohuangli
```

安装后重启 Home Assistant，再添加集成：

```text
设置 → 设备与服务 → 添加集成 → Chinese Almanac / chinese
```

配置要求：

- 集成名称保持默认“中国老黄历”，避免卡片前缀不可预测。
- 不启用生日管理。
- 不启用事件管理。
- 不启用通知。
- 不启用 AI 预测。
- 语言选择简体中文。

卡片默认前缀按插件文档使用：

```yaml
prefix: chinese_almanac_
```

安装后必须在开发者工具中确认实际实体 ID；若前缀不同，应只修改 Dashboard 中的 `prefix`，不要批量重命名插件的全部实体。

## 6. 配置文件重构

### 6.1 拆分模板目录

当前：

```yaml
template: !include templates/yuedu_ui.yaml
```

改为：

```yaml
template: !include_dir_merge_list templates
```

现有 `yuedu_ui.yaml` 已是列表格式，可继续工作。

新增：

```text
deploy/homeassistant/config/templates/yuedu_weather_calendar.yaml
```

用途：

- 对天气实体做可用性与中文摘要。
- 对老黄历实体做首页摘要。
- Dashboard 只引用 `sensor.yuedu_*` 语义实体。

---

### 6.2 新增语义模板

`templates/yuedu_weather_calendar.yaml` 建议内容：

```yaml
- binary_sensor:
    - name: 悦都天气数据可用
      unique_id: yuedu_weather_available
      icon: mdi:weather-partly-cloudy
      state: >-
        {{ states('weather.yuedu_home')
           not in ['unknown', 'unavailable', 'none', 'None', ''] }}

- sensor:
    - name: 悦都天气摘要
      unique_id: yuedu_weather_summary
      icon: mdi:weather-partly-cloudy
      state: >-
        {% set entity = 'weather.yuedu_home' %}
        {% set value = states(entity) %}
        {% set temp = state_attr(entity, 'temperature') %}
        {% set humidity = state_attr(entity, 'humidity') %}
        {% set map = {
          'sunny': '晴',
          'clear-night': '晴朗夜间',
          'partlycloudy': '多云间晴',
          'cloudy': '多云',
          'rainy': '有雨',
          'pouring': '大雨',
          'lightning-rainy': '雷阵雨',
          'windy': '有风',
          'fog': '有雾',
          'snowy': '有雪'
        } %}
        {% if value in ['unknown', 'unavailable', 'none', 'None', ''] %}
          天气数据暂不可用
        {% else %}
          {{ map.get(value, value) }}
          {% if temp is number %} · {{ temp | round(1) }}°C{% endif %}
          {% if humidity is number %} · 湿度 {{ humidity | round(0) }}%{% endif %}
        {% endif %}
      attributes:
        available: >-
          {{ states('weather.yuedu_home')
             not in ['unknown', 'unavailable', 'none', 'None', ''] }}

    - name: 悦都今日历法摘要
      unique_id: yuedu_almanac_summary
      icon: mdi:calendar-star
      state: >-
        {#
          安装中国老黄历后，根据开发者工具中的真实实体 ID
          替换下面三个占位实体。
        #}
        {% set lunar = states('sensor.REPLACE_ALMANAC_LUNAR') %}
        {% set term = states('sensor.REPLACE_ALMANAC_SOLAR_TERM') %}
        {% set festival = states('sensor.REPLACE_ALMANAC_FESTIVAL') %}
        {% set invalid = ['unknown', 'unavailable', 'none', 'None', ''] %}
        {% if lunar in invalid %}
          农历数据暂不可用
        {% else %}
          {{ lunar }}
          {% if term not in invalid %} · {{ term }}{% endif %}
          {% if festival not in invalid and festival != '暂无节日' %}
            · {{ festival }}
          {% endif %}
        {% endif %}
```

注意：

- Codex 不得猜测老黄历实体 ID。
- 若无法从运行实例读取实体 ID，必须保留显式 `REPLACE_...` 占位并在部署文档标明。
- 天气实体 ID 可以按方案固定为 `weather.yuedu_home`。

## 8. 手机端 YAML 设计

### 8.1 首页天气卡

在首页新增一个独立 `grid` section，放在 2.5D 户型图区之后、家庭状态 Chips 之前。

```yaml
- type: grid
  cards:
    - type: custom:mushroom-title-card
      title: 今日信息
      subtitle: 时间、天气与家庭安排

    - type: conditional
      conditions:
        - condition: state
          entity: binary_sensor.yue_du_tian_qi_shu_ju_ke_yong
          state: "on"
      card:
        type: custom:clock-weather-card
        entity: weather.yuedu_home
        title: 悦都
        sun_entity: sun.sun
        locale: zh-CN
        time_format: 24
        time_pattern: HH:mm
        date_pattern: yyyy年M月d日 cccc
        weather_icon_type: line
        animated_icon: true
        forecast_rows: 4
        show_humidity: true
        hide_today_section: false
        hide_forecast_section: false
        hourly_forecast: false
        use_browser_time: false

    - type: conditional
      conditions:
        - condition: state
          entity: binary_sensor.yue_du_tian_qi_shu_ju_ke_yong
          state: "off"
      card:
        type: custom:mushroom-template-card
        entity: sensor.yue_du_tian_qi_zhai_yao
        primary: 天气服务暂不可用
        secondary: 稍后会自动恢复，不影响家庭设备控制
        icon: mdi:weather-cloudy-alert
        icon_color: amber
        multiline_secondary: true

    - type: custom:mushroom-template-card
      entity: sensor.yue_du_jin_ri_li_fa_zhai_yao
      primary: 今日万年历
      secondary: "{{ states(entity) }}"
      icon: mdi:calendar-star
      icon_color: amber
      multiline_secondary: true
      tap_action:
        action: navigate
        navigation_path: /yuedu-home/agenda
```

注意：

- 模板实体的最终 entity_id 由 HA 中文 slugify 结果决定，部署后应在开发者工具确认。
- 若项目希望完全固定 entity_id，可在实体注册后手工改成英文稳定 ID，再同步 YAML。
- 不要把天气卡塞入 `picture-elements`，避免坐标维护和文字可读性问题。

## 10. 自动化扩展建议

本期只实现两条低风险自动化，且必须以天气/日历实体可用为前提。

### 10.1 降雨前提醒收衣服

触发方式建议使用定时检查 + `weather.get_forecasts`，不要依赖旧版 forecast 属性。

逻辑：

```text
每小时检查一次
→ 获取未来 3～6 小时预报
→ 若预计降雨且洗衣机最近完成/阳台可能晾衣
→ 向家庭手机发送提醒
```

本期可以只创建文档和禁用状态的自动化模板，不默认启用。

### 10.2 家庭事件提前提醒

使用 Calendar Trigger：

```text
事件开始前 30 分钟
→ 仅针对 calendar.yuedu_family
→ 发送家庭提醒
```

自动化 mode 使用 `queued` 或 `parallel`，不要使用 `single`，避免同一时间多个事件互相丢失。

## 11. 依赖检查脚本

新增：

```text
deploy/homeassistant/scripts/check-weather-calendar.sh
```

建议内容：

```bash
#!/usr/bin/env bash
set -euo pipefail

CONFIG_DIR="${1:-$(cd "$(dirname "$0")/.." && pwd)/config}"

required_files=(
  "$CONFIG_DIR/www/community/clock-weather-card/clock-weather-card.js"
  "$CONFIG_DIR/www/community/calendar-card-pro/calendar-card-pro.js"
)

failed=0
for file in "${required_files[@]}"; do
  if [[ ! -f "$file" ]]; then
    echo "[MISSING] $file"
    failed=1
  else
    echo "[OK] $file"
  fi
done

if [[ ! -d "$CONFIG_DIR/custom_components/chinese_calendar" ]]; then
  echo "[OPTIONAL MISSING] Chinese Almanac is not installed."
else
  echo "[OK] Chinese Almanac integration exists."
fi

exit "$failed"
```

注意：HACS 的实际落盘目录大小写可能与示例不同。Codex 应检查当前 `www/community` 的真实目录并修正脚本，不得凭空假设。

## 14. 验收标准

### 14.1 配置级

- `ha core check` 或 HA“检查配置”通过。
- Home Assistant 重启后无新增 YAML 错误。
- 日志中无 `Custom element doesn't exist`。
- 日志中无 Chinese Almanac 初始化异常。
- 页面不存在红色错误卡。

### 14.2 数据级

- `weather.yuedu_home` 可用。
- daily forecast 可返回。
- hourly forecast 可返回，或已按方案降级为 daily。
- `calendar.yuedu_family` 可显示测试事件。
- `calendar.yuedu_birthdays` 可显示全天事件。
- 农历摘要不显示 `unknown`/`unavailable`。

### 14.3 UI 级

手机端：

- 首页首屏仍以全屋状态和户型图为核心。
- 今日信息在户型图之后。
- 天气卡不横向溢出。
- 日历事件最多先展示 5 条，可点击展开。
- 完整黄历在独立视图中。

墙屏端：

- 三列布局不拥挤。
- 天气时间字体可在 2～3 米距离识别。
- 家庭日历不显示私密描述与地点。
- 相机卡仍可正常显示或保持明确离线态。

### 14.4 降级级

卸载或暂时禁用第三方前端卡后：

- 可用原生 `weather-forecast` 验证天气。
- 可用原生 `calendar` 验证事件。
- 设备控制、户型图、门锁、空调、洗衣机不受影响。
- 万年历故障不影响天气和家庭日历。
