## 1. 升级原则（对齐现代前端规范）

1. **一致性（Consistency）**：全站共用一套设计令牌与卡片语言，杜绝风格分裂。
2. **状态可见（Visibility of state）**：状态变化有清晰视觉反馈，离线/异常有容错态。
3. **操作不离场（In-place control）**：深度控制用弹窗而非整页跳转。
4. **层级与留白（Hierarchy & spacing）**：信息有主次，空间页有"进入房间"的沉浸感。
5. **可达性（Accessibility）**：触控目标 ≥44px、对比度达标、图标配文字、可朗读。
6. **响应式（Responsive）**：iPhone 单列、平板多列、墙屏常驻一套布局。

## 2. 升级项清单（按优先级）

### P0 — 设计系统底座（必须先行，其他项依赖它）

**U0. 引入 card-mod，建立"令牌下沉"机制**
- 在 `config/www/community/` 加入 `card-mod`（HACS 安装后复制 JS），并在 `configuration.yaml` 确保前端可加载。
- 目的：把 `悦都暖石` 已定义的令牌（圆角 `20px`、间距、阴影、强调色 `#167D7A`、文字色）**下沉到弹窗与第三方卡内部细节**，解决目前 Bubble Pop-up、Mushroom 内部间距与圆角不完全受主题控制的问题。
- 改动文件：`config/www/community/`（新增 card-mod）、`config/dashboards/dashboard-v2.yaml`（各卡加 `card_mod` 样式引用令牌变量）。

**U1. 统一间距 / 圆角 / 字体令牌**
- 在 `themes/yuedu-warm.yaml` 增补一组 UI 令牌：`--yuedu-radius`(20px)、`--yuedu-gap`(12px)、`--yuedu-font`(Inter/system)、弹窗最大宽度等。
- 全站卡片与 Pop-up 统一引用，避免散落的硬编码 `padding/box-shadow`。

**U2. 状态驱动动效（轻量反馈）**
- 为开关态、状态色变化增加 150–200ms 缓动过渡（`card-mod` + `transition`）。
- 操作成功用 HA 原生 `toast`/持久通知确认（已有 `persistent_notification`，可升级为更轻的提示）。

### P1 — 交互与空间体验

**U3. 户型图重构为 Floorplan Card（SVG）**
- 当前：`dashboard-v2.yaml` 中**首页小图、地图页大图、各房间页小图**都用 `picture-elements` 的百分比 `left/top` 坐标定位，新增设备需反复调坐标，且对读屏不友好。
- 升级：改用 Floorplan Card（SVG 元素 + 实体映射）。同一份 SVG 可复用到多视图；设备新增只改配置；点击热区更精准、可达性更好。
- 改动文件：`config/dashboards/dashboard-v2.yaml`（替换三处 picture-elements）、`config/www/floorplan/`（新增 SVG 底图，原 `yuedu-home-2p5d.png` 保留作参考）。

**U4. Pop-up 就地控制深化**
- 现状仅有 3 个 Bubble Pop-up（摄像机 / 主卧空调 / 阳台洗衣机）。
- 新增：
  - 门锁只读安全详情 Pop-up（`#yuedu-living-lock`：门状态/锁状态/电量，明确"不提供远程开锁"）；
  - 快捷模式确认 Pop-up（离家/睡眠执行前二次确认，复用已有 `confirmation`）；
  - 预留空间引导 Pop-up（次卧/厨房卫浴："即将支持"的能力预览）。
- 统一 Pop-up 打开动效（slide-up / fade），统一头部与关闭交互。

**U5. 空间沉浸背景层**
- 为"客厅 / 主卧 / 阳台"各 `sections` 视图加模糊房间照片/渲染图背景（通过 `card-mod` 给 section 容器加 `background`），营造"进入房间"感，而非纯设备列表。
- 改动文件：`config/dashboards/dashboard-v2.yaml` 各空间视图 + `config/www/`（新增背景图资源）。

**U6. 信息层级微调**
- 首页"常用空间"四卡与"快捷模式"已分层；建议为各 section 增加更明确的分隔标题与留白节奏，避免卡片平铺感。

### P2 — 可达性、多端与智能化

**U7. 可达性校验**
- 校验 `悦都暖石` 在主要文字/背景组合的对比度达 WCAG AA；确保图标均有文字标签；触控目标 ≥44px（Bubble 标记、chips 重点检）。

**U8. 响应式与墙屏（Kiosk）**
- `sections` 已支持 `max_columns`；为平板/桌面引入 `max_columns: 3/4` 的视图变体。
- 引入 Kiosk Mode（或 ha-fusion 复用现有语义层）作为客厅/玄关墙屏前端，常驻家庭地图。

**U9. 暗色模式决策**
- 主题刻意无 dark mode（避免木色空间入黑灰底）。若未来需夜间使用：补一套 `lovelace-dark` 变量并验证 2.5D 底图可读性，或提供"跟随系统"开关。建议先与业主确认需求再实施。

**U10. 空状态与未来扩展引导**
- 次卧/厨房卫浴当前为静态文案；加"即将支持"的骨架/引导态，未来设备接入时平滑出现，体现系统的成长性。

**U11. AI 中枢（skill 方向，可选）**
- 接入 Home Assistant MCP，使本目录部署的 HA 实例可被兼容 MCP 的 AI Agent 程序化读/控，与现有语义层形成"人看 + AI 管"双通道。

## 3. 实施路线（建议顺序）

| 阶段 | 内容 | 产出入本目录的文件 |
| --- | --- | --- |
| **阶段 A（P0 底座）** | U0 card-mod + U1 令牌 + U2 动效 | `www/community/card-mod`、`themes/yuedu-warm.yaml`、`dashboards/dashboard-v2.yaml` |
| **阶段 B（P1 交互）** | U3 Floorplan Card + U4 Pop-up 扩展 + U5 空间背景 + U6 层级 | `dashboards/dashboard-v2.yaml`、`www/floorplan/*.svg`、`www/背景图` |

> 建议**先完成阶段 A 再推进 B**：令牌与 card-mod 是后续所有视觉统一的基础，避免反复返工。

## 4. 风险与注意

- **card-mod 版本**：需与当前 HA `:stable` 兼容，安装时锁定版本并写入部署说明。
- **Floorplan Card 迁移成本**：需把现有三处 `left/top` 坐标映射为 SVG 元素坐标，建议先在"地图页"单点验证再推广到首页小图与各房间页。
- **背景图资源**：空间背景图需业主提供实拍/渲染图，避免引入版权不明图库。
- **不要破坏语义层约定**：所有 UI 升级继续只引用 `sensor.yue_du_*` 语义实体，新增设备先建语义传感器（维持 `templates/yuedu_ui.yaml` 单一收敛点）。
- **HA 镜像版本**：本目录 `docker-compose.yml` 仍用 `:stable`，正式部署前建议锁定具体 tag（如 `:2026.7.x`）以保证 UI/集成行为可复现。

---

## 5. 小结

本目录已是生产级 v4 配置，UI 升级不缺"框架"，缺的是**设计系统的统一落地**与**交互沉浸感**。优先做 U0–U2（令牌 + card-mod + 动效）打底，再做 U3–U5（Floorplan Card + Pop-up 扩展 + 空间背景）提升体验，最后补可达性/多端/暗色/AI。所有改动均局限在 `config/dashboards/dashboard-v2.yaml`、`config/themes/yuedu-warm.yaml`、`config/www/` 三处，便于版本管理与回滚。
