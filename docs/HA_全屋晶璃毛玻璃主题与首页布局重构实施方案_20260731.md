# Home Assistant「全屋晶璃」毛玻璃主题与 `/yuedu-home/home` 首页重构实施方案

> 项目：`QiudaoyuDev/ha`  
> 评审基线：`main` 分支，最新评审提交 `67bac9f01cd2716bcf53d436ca5bad3af34c1770`  
> 目标页面：`/yuedu-home/home`  
> 参考主题：`wessamlauf/homeassistant-frosted-glass-themes`（Frosted Glass v1.3 思路）  
> 文档用途：可直接交给 Codex 作为实施依据  
> 日期：2026-07-31

---

## 0. 结论

当前首页的问题不是某一张卡片不好看，而是**信息架构、视觉层级和交互入口同时失控**：

1. 首页在两列 Sections 中连续堆叠户型图、天气时钟、天气趋势、万年历、状态 Chips、空间入口、快捷模式、预留空间和多个 Bubble 弹层，导致首屏缺少唯一焦点。
2. 同一设备状态在户型图标签、顶部 Chips、常用空间卡、家庭地图页、房间页中重复出现，信息冗余明显。
3. 当前 `悦都暖雾` 只是“悦都暖石暖色配色 + 轻量透明卡片”，大量米色、棕色、青绿色和硬编码的 `#FFF9F1`、`#167D7A` 仍然决定整体风格，并不是独立完整的毛玻璃设计体系。
4. 户型图、设备标记、天气卡、日历卡、Bubble 弹层和设备控制器并未共享统一的玻璃层级、状态色、边框、阴影、圆角及交互反馈。
5. 首页既承担“总览”，又承担“深度控制”和“完整天气日历”，职责过多。

本方案不在现有首页上继续叠加，而是执行一次**替换式重构**：

- 新建完全独立的 `全屋晶璃` 主题，不继承 `悦都暖雾` 的暖石底色。
- 首页改成“家庭状态中枢”，只回答四个问题：
  1. 家里是否安全；
  2. 哪些设备正在运行；
  3. 当前是否有需要处理的异常或任务；
  4. 今天接下来有什么天气和家庭安排。
- 2.5D 户型图成为首页唯一视觉主角。
- 深度设备控制统一进入 Bubble 弹层或房间页。
- 天气与日历首页只保留摘要，完整内容移至 `/yuedu-home/agenda`。
- 为移动端、桌面端和墙屏分别设定响应式信息密度。
- 同时提供标准毛玻璃和 Lite 无模糊降级版，解决性能与下拉菜单兼容问题。

# 1. 当前实现评估

## 1.1 当前首页结构

当前 `deploy/homeassistant/config/dashboards/dashboard-v2.yaml` 中，`home` 视图：

```yaml
path: home
type: sections
max_columns: 2
theme: 悦都暖雾
```

页面依次包含：

1. 标题、全屋状态、2.5D 户型图；
2. 天气时钟、未来 5 日天气、天气不可用提示、今日万年历；
3. 门锁/空调/洗衣 Chips、常用空间四宫格；
4. 离家模式、睡眠模式；
5. 卧室 B、厨房与卫浴预留入口；
6. 客厅摄像机 Bubble 弹层；
7. 主卧空调和循环扇 Bubble 弹层；
8. 阳台洗衣机 Bubble 弹层。

从 YAML 结构看，Bubble 弹层虽然默认隐藏，但仍与首页内容混在同一个视图配置中；普通内容又被拆成多个同级 Section。`max_columns: 2` 会让不同业务模块按 Sections 流式排布，造成视觉上左右两列高度不一致、阅读顺序不稳定。

## 1.2 首页主要问题

### 1.2.1 没有单一视觉焦点

户型图、天气时钟和未来天气都属于大体积卡片，彼此竞争。用户进入首页后不知道应该先看：

- 全屋状态；
- 户型；
- 天气；
- 日历；
- 设备入口；
- 快捷模式。

正确首页应让户型图占据主视觉，天气和日程只作为右侧上下文信息。

### 1.2.2 信息重复

以主卧空调为例，当前至少出现在：

- 首页户型图状态标签；
- 首页状态 Chips；
- 首页“主卧舒适”卡；
- 家庭地图页；
- 主卧房间页；
- 首页 Bubble 弹层。

摄像机、洗衣机也存在相同问题。

应改为：

- 首页户型图：空间定位与状态入口；
- 首页状态条：仅展示异常、运行中或重要安全信息；
- Bubble：快速控制；
- 房间页：完整设备管理；
- 家庭地图页：完整空间与设备分布。

### 1.2.3 天气内容重复

首页同时展示：

- `clock-weather-card`；
- 原生 `weather-forecast`；
- 今日万年历摘要。

而 `/yuedu-home/agenda` 已经有：

- 完整天气；
- 逐小时天气；
- 7 日家庭日历；
- 完整万年历。

首页不应再次展示完整未来 5 日趋势。首页只需“当前天气 + 今日高低温 + 下一场天气变化”，详细趋势进入 Agenda。

### 1.2.4 主题仍被悦都暖石风格控制

当前主题文件明确使用：

- `#F1E7DA`、`#E9DDCF` 等暖米色背景；
- `#87593B` 棕色主色；
- `#167D7A` 青绿色强调色；
- `rgba(255, 249, 241, ...)` 暖白卡片；
- 棕色阴影。

户型图元素中还存在大量硬编码：

```yaml
background: '#FFF9F1'
border: '2px solid #167D7A'
color: '#155E5A'
```

因此，即使增大 `backdrop-filter`，整体仍是“悦都暖色主题加透明”，不是独立毛玻璃主题。

### 1.2.5 毛玻璃层级不完整

完整毛玻璃体系应覆盖：

- 全局背景；
- Header；
- Sidebar；
- 普通卡片；
- Dialog；
- Pop-up；
- Chips；
- 输入控件；
- 状态徽标；
- 地图标记；
- Light/Dark 模式；
- 性能降级。

当前主题主要只处理普通 `ha-card`，并主动排除了 Bubble、Chips 和户型图，但没有为这些组件设计新的专用玻璃表面。

### 1.2.6 户型图与标记风格割裂

2.5D 户型图是写实空间图，但标记使用实色暖白圆、青色边框和较重阴影。切换毛玻璃后，标记不能继续使用这些硬编码，否则会像“旧主题控件贴在新主题上”。

### 1.2.7 控制入口不够统一

当前存在：

- 户型图图标跳房间；
- 户型图状态标签跳 Hash 弹层；
- 常用空间卡跳 Hash；
- 房间卡跳房间；
- 状态卡有时 `more-info`，有时 `toggle`；
- 快捷模式直接执行 Script。

同一类型元素的点击行为不一致。应建立明确规则：

- **单击设备标记：打开快速控制弹层**；
- **长按：打开 Home Assistant `more-info`**；
- **点击空间名称：进入房间页**；
- **首页不直接执行高风险动作**；
- **停止洗涤、关闭安防设备、离家模式等动作必须确认**。

# 2. 目标设计体系

新主题名称建议：

- 标准主题：`全屋晶璃`
- Lite 主题：`全屋晶璃 Lite`
- 固定浅色：`全屋晶璃 Light`
- 固定深色：`全屋晶璃 Dark`

主题名称不再带“暖雾”“暖石”或原有悦都配色语义。

## 2.1 设计原则

### 原则 A：玻璃是表面层，不是内容滤镜

禁止直接模糊：

- 户型底图；
- 摄像机画面；
- 图标本体；
- 文本；
- 温度刻度；
- 进度条；
- 下拉菜单内容。

模糊只应用在内容后方的玻璃层或伪元素上。

### 原则 B：一屏一个主角

首页主角是 2.5D 户型图。天气、日历、模式和状态都必须降为辅助层。

### 原则 C：状态优先于控制

首页先让用户知道设备状态，再提供控制。深度控制不应平铺在首页。

### 原则 D：透明度不能损害可读性

浅色模式和深色模式必须分别设计文本、背景和玻璃 Tint，不能只依赖浏览器自动反色。

### 原则 E：交互反馈必须可感知

所有可执行控件至少具备：

- 默认态；
- Hover/按下态；
- 执行中态；
- 成功态；
- 失败或离线态；
- 禁用态。

# 3. 首页信息架构重构

## 3.1 桌面端与平板横屏布局

建议主布局采用 12 列概念，落地时继续使用 Home Assistant `sections`，但只保留 3 个主要 Section。

```text
┌──────────────────────────────────────────────────────────────┐
│ A. 顶部家庭状态栏：标题 / 全屋状态 / 时间 / 模式入口         │
├───────────────────────────────────┬──────────────────────────┤
│                                   │ B1. 当前天气              │
│                                   ├──────────────────────────┤
│ C. 2.5D 户型图                    │ B2. 下一条家庭日程        │
│    - 房间热区                     ├──────────────────────────┤
│    - 设备状态标记                 │ B3. 今日历法摘要          │
│    - 运行/异常状态                ├──────────────────────────┤
│                                   │ B4. 需要关注              │
├───────────────────────────────────┴──────────────────────────┤
│ D. 运行中设备 / 关键状态条：门锁、空调、摄像机、洗衣机       │
├──────────────────────────────────────────────────────────────┤
│ E. 快捷模式：离家、睡眠、回家（未来）、观影（未来）          │
└──────────────────────────────────────────────────────────────┘
```

推荐宽度关系：

- 户型图区域：约 65%；
- 右侧信息栏：约 35%；
- 顶部状态栏：全宽；
- 底部状态和快捷模式：全宽。

在当前 Home Assistant 实例支持 `grid_options` 时：

- 顶部状态栏设置为全宽；
- 户型图 Section 约占 7/12；
- 信息栏 Section 约占 5/12；
- 状态与模式使用全宽 Section。

如果当前版本或 YAML 模式对 `grid_options` 支持不稳定，则使用：

- 第一 Section：顶部状态与户型图；
- 第二 Section：天气、日程、关注项；
- 第三 Section：设备状态与场景；
- 保持 `max_columns: 2`，但减少 Section 数量，禁止继续使用 6～7 个同级 Section。

## 3.2 首页顶部家庭状态栏

顶部不再使用单独标题卡 + 单独全屋状态卡，而是合并成一个轻量 Hero。

内容建议：

- 左侧：
  - `全屋晶璃`
  - 当前日期和星期；
- 中部：
  - 全屋状态；
  - 在线设备数；
  - 正在运行设备数；
- 右侧：
  - 离家模式；
  - 睡眠模式；
  - 进入家庭地图；
  - 进入天气日历。

视觉要求：

- 外层为中等透明玻璃；
- 高度控制在 72～88px；
- 不使用独立大图标卡；
- 状态正常时不高亮整卡，只显示绿色小状态点；
- 有异常时才显示琥珀或红色提示。

## 3.3 户型图主卡

首页户型图只承担：

1. 空间导航；
2. 关键设备状态；
3. 异常定位；
4. 快速控制入口。

不再在首页户型图上重复显示长状态文本，例如：

- “设备在线”；
- “正在等待米家连接”；
- “空调运行中 · 26°”。

首页地图标记只显示：

- 图标；
- 必要时的短状态值，如 `26°`、`洗涤中`；
- 离线点；
- 告警点。

完整文本进入弹层或右侧“需要关注”。

## 3.4 右侧上下文信息栏

### 3.4.1 当前天气

首页只保留一个紧凑天气模块：

- 当前温度；
- 天气图标；
- 今日高低温；
- 湿度；
- 降水概率；
- 未来 3～6 小时趋势或最多 3 日简要趋势。

删除首页第二张原生 `weather-forecast` 卡。

点击天气模块进入 `/yuedu-home/agenda`。

### 3.4.2 下一条家庭日程

只展示：

- 下一条事件标题；
- 时间；
- 倒计时；
- 日历类型。

若 24 小时内无事件，则显示“今天暂无家庭安排”。

点击进入 Agenda。

### 3.4.3 今日历法摘要

首页只显示一行：

- 农历；
- 节气或节日；
- 不显示完整宜忌。

完整老黄历留在 Agenda。

### 3.4.4 需要关注

这是当前首页缺失的重要模块。仅在有内容时显示：

- 门锁异常；
- 设备离线；
- 洗衣完成；
- 摄像机不可用；
- 天气服务不可用；
- 日历服务不可用。

状态正常时不占用大卡，仅在顶部状态栏显示“全屋正常”。

## 3.5 运行中设备状态条

首页状态条不再无条件展示所有设备。规则：

- 正在运行：显示；
- 有任务：显示；
- 有异常：显示；
- 安全类设备：常驻显示；
- 闲置且正常的普通设备：隐藏或低权重显示。

当前设备建议：

| 设备 | 首页展示规则 |
|---|---|
| 门锁 | 常驻，只读 |
| 主卧空调 | 运行或离线时展示 |
| 循环扇 | 运行或离线时展示 |
| 客厅摄像机 | 守护、视频流异常或离线时展示 |
| 洗衣机 | 洗涤、暂停、完成或离线时展示 |

## 3.6 快捷模式

首页场景只保留 2～4 个最常用动作。

第一阶段：

- 离家模式；
- 睡眠模式。

交互要求：

- 离家模式：执行前确认；
- 睡眠模式：单击可执行，但执行后显示反馈；
- 执行中按钮进入 Loading；
- 执行成功显示 1～2 秒状态反馈；
- 执行失败显示 Home Assistant 通知或 Toast；
- 不使用危险的直接门锁开关。

## 3.7 预留空间处理

“卧室 B”“厨房与卫浴”等无设备空间不应继续占据首页主区域。

处理方式：

- 从首页移除；
- 保留在家庭地图或空间导航页；
- 设备接入后再动态出现在首页。

# 4. 移动端布局

移动端顺序固定为：

1. 顶部家庭状态栏；
2. 关键状态 Chips；
3. 户型图；
4. 需要关注；
5. 当前天气；
6. 下一条日程；
7. 快捷模式；
8. 运行中设备。

移动端要求：

- 户型图宽度 100%；
- 地图标记最小点击尺寸 44×44px；
- 设备标记避免长文本；
- 两列设备卡，窄屏降为单列；
- 首页不展示未来 5 日完整天气；
- Bubble 弹层采用底部抽屉形态；
- 主要按钮放在拇指可达区域；
- 控制弹层最大高度约 85vh，内部滚动；
- iPhone 安全区使用 `env(safe-area-inset-bottom)` 留白。

# 5. 墙屏布局

当前 `dashboard-wall.yaml` 也使用 `悦都暖雾`，并把户型、状态、天气、日历、摄像机依次放进多个 Section。应同步切换为“全屋晶璃”。

横屏墙屏建议：

```text
┌──────────────────────┬─────────────────┬─────────────────┐
│                      │ 当前天气         │ 门锁 / 安防     │
│                      ├─────────────────┤ 空调 / 风扇     │
│  大尺寸 2.5D 户型图  │ 家庭日程         │ 洗衣任务        │
│                      ├─────────────────┤ 快捷模式         │
│                      │ 今日历法         │                 │
└──────────────────────┴─────────────────┴─────────────────┘
```

要求：

- 户型图占 50%～60%；
- 右侧控制卡使用 Lite 玻璃或较低 Blur，避免墙屏持续渲染卡顿；
- 摄像机画面只有用户主动点击后播放；
- 视频容器保持纯黑或深灰，不加模糊；
- 墙屏默认优先使用 `全屋晶璃 Lite`；
- 有条件时使用 Kiosk Mode 隐藏 Header/Sidebar；
- 无 Kiosk Mode 时布局仍然可正常使用。

# 6. 完整毛玻璃主题设计

## 6.1 参考项目中应吸收的机制

参考 `homeassistant-frosted-glass-themes` 的以下思路：

1. `ha-card` 本体透明；
2. 使用 `ha-card::before` 作为独立玻璃层；
3. 使用统一的 Tint、Blur、Saturate、Inset Glow；
4. Header、Sidebar、Dialog 分别定义玻璃参数；
5. Light/Dark 模式分别定义文本和背景；
6. 为低性能设备提供 Lite 版本；
7. 对 Mushroom Title、Bubble 外层、Chips 外层等特殊组件做排除；
8. 使用完整的 Home Assistant 色阶 Token；
9. 不对所有深层 Shadow DOM 强制注入样式；
10. 对 Dropdown/Select 兼容问题使用 Lite 或高不透明弹层降级。

## 6.2 新主题色板

主题不再使用米棕色。

### Light

| Token | 建议值 |
|---|---|
| 主背景 | 本地蓝紫灰渐变背景图 |
| Primary | `#7486FF` |
| Accent | `#59D4C7` |
| 主文本 | `rgba(18, 24, 46, 0.96)` |
| 次文本 | `rgba(18, 24, 46, 0.68)` |
| 玻璃 Tint | `rgba(255, 255, 255, 0.18)` |
| 卡片基础透明色 | `rgba(242, 246, 255, 0.12)` |
| 边框 | `rgba(255, 255, 255, 0.42)` |
| 内高光 | `rgba(255, 255, 255, 0.28)` |
| 阴影 | `0 14px 36px rgba(34, 47, 94, 0.16)` |

### Dark

| Token | 建议值 |
|---|---|
| 主背景 | 本地深蓝黑渐变背景图 |
| Primary | `#8EA0FF` |
| Accent | `#64E1D3` |
| 主文本 | `rgba(244, 247, 255, 0.96)` |
| 次文本 | `rgba(226, 233, 255, 0.70)` |
| 玻璃 Tint | `rgba(20, 27, 50, 0.34)` |

## 6.3 玻璃层级

禁止所有组件都使用同样 Blur。

| 层级 | 使用场景 | Blur |
|---|---|---|
| G0 | 户型图、视频、图表 | 0 |
| G1 | Chips、设备 Marker | 8～10px |
| G2 | 普通信息卡 | 14～18px |
| G3 | Header、Sidebar、Pop-up | 18～24px |
| Lite | 墙屏、低性能设备、Dropdown 问题 | 0 |

## 6.4 圆角与间距

| 项目 | 数值 |
|---|---|
| 大型主卡 | 24px |
| 普通卡 | 20px |
| 小卡/Chip | 14～16px |
| 弹层 | 28px |
| 卡片间距 | 14～18px |
| 卡片内边距 | 16～20px |
| 最小点击尺寸 | 44px |
| 地图设备 Marker | 44～48px |

## 6.5 动效

- Hover：`translateY(-1px)`；
- Press：`scale(0.98)`；
- 状态变化：背景和边框 180～240ms；
- Pop-up：淡入 + 轻微上移；
- 禁止大面积持续漂浮动画；
- 对 `prefers-reduced-motion: reduce` 关闭位移动效；
- 离线状态不闪烁；
- 告警可以使用一次性柔和 Pulse，不使用无限红色闪烁。

# 8. 特殊卡片适配规则

## 8.1 Mushroom Title

标题卡不加独立玻璃背景：

```css
:host(mushroom-title-card) ha-card,
:host(mushroom-title-card) ha-card::before {
  background: none !important;

  border: none !important;
  content: none !important;
}
```

避免每个区块标题都变成一张厚重卡片。

## 8.2 Mushroom Chips

外层透明，单个 Chip 使用 G1 玻璃。

- 正常状态：低透明；
- 运行状态：Primary 边框；
- 告警状态：Warning/Error Tint；
- Chip 高度至少 36px；
- 移动端点击区域通过 Padding 扩展到 44px。

## 8.3 Mushroom Entity/Template/Climate/Fan/Select

普通 Entity/Template 使用 G2。

Climate/Fan/Select：

- 外层使用 G2；
- 内部 Slider、Select、按钮不再生成第二层伪元素；
- Select 菜单使用高不透明背景；
- Dropdown 错位时自动切换 Lite 或对该控件禁用 Blur。

## 8.4 Bubble Card

参考主题会排除 Bubble Card 的全局玻璃，原因是 Bubble 深层嵌套容易产生重复模糊。因此本项目应：

1. 全局排除 Bubble 外层；
2. 对每个 Pop-up 的最外层容器单独应用 G3；
3. 内部 Mushroom 卡片设为透明或 G1；
4. 不允许 Bubble 外层和内部每张卡都重复 Blur；
5. 弹层背景必须比普通卡更不透明，保证设备控制可读性。

## 8.5 Clock Weather Card

首页天气：

- 删除重复边框；
- 背景由主题接管；
- 天气图标保持清晰；
- 只显示当前天气和精简趋势；
- 文字颜色使用主题 Token；
- 动画图标在 Lite 或 `prefers-reduced-motion` 下关闭。

## 8.6 原生 Weather Forecast

从首页移除，仅保留在 Agenda。

Agenda 中：

- 玻璃外框；
- 天气行使用透明分隔；
- 降水和温度颜色统一；
- 图表不做 Blur。

## 8.7 Calendar Card Pro

- 外层 G2；
- 月份标题透明；
- 日期胶囊 G1；
- 事件行不单独形成厚重玻璃卡；
- 事件 Accent 使用主题状态色；
- 地址、描述等隐私信息继续隐藏；
- 首页只显示下一事件，不直接复用完整 7 日卡。

## 8.8 Almanac Card

- 完整卡仅在 Agenda；
- 首页只使用 `sensor.yue_du_jin_ri_li_fa_zhai_yao`；

# 10. 设备控制弹层适配

## 10.1 通用弹层结构

```text

- 图标
- 设备名
- 房间
```

- 当前室温；
- 空调开关；
- 目标温度；
- HVAC 模式；
- 风速；

高级控制折叠：

- 送风方向；
- 导风板；
- 睡眠档；
- 循环扇角度；
- 节能；
- 防霉干燥；

- 实时画面或占位图；

次级：

- 夜视模式；

- 水温；

# 15. 交互验收标准

## 15.1 首页

- 进入首页 1 秒内能够识别全屋是否正常；
- 户型图是首屏最大元素；
- 首页不再同时出现两张天气趋势卡；
- 同一设备在首页不出现超过两个入口；
- 无设备的房间不占首页空间；
- 所有设备 Marker 点击行为一致；
- 首页无直接远程开锁能力。

## 15.2 视觉

- Dashboard 中不再出现 `#FFF9F1`、`#167D7A`、`#87593B` 等旧主题硬编码；
- Light/Dark 均能保持正文对比度；
- 户型图和视频清晰无模糊；
- 普通卡、Pop-up、Chip、Marker 具有统一的玻璃语言；
- 深层嵌套不出现双边框或三层 Blur；
- 标题卡没有多余玻璃背景。

## 15.3 控制

- 离线设备不显示可执行控件；
- 停止洗涤需要确认；
- 离家模式需要确认；
- 门锁只读；
- 关闭摄像机电源在守护场景需要确认；
- 操作后状态能够在合理时间内反馈；
- 服务失败不会让 UI 假装成功。

## 15.4 性能

- 桌面端滚动无明显卡顿；
- iPhone 页面滑动稳定；
- 墙屏运行 30 分钟无持续掉帧；
- Lite 主题无 `backdrop-filter`；
- Dropdown/Select 可正常显示；
- 动画图标不会导致墙屏持续高负载。

# 20. 最终目标状态

改造完成后，首页应呈现以下体验：

- 背景是独立的蓝紫灰或深蓝黑环境背景；
- 所有主要卡片像悬浮在背景上的半透明玻璃；
- 户型图保持清晰，是页面最大视觉元素；
- 设备 Marker 像轻量玻璃按钮，不再是暖白实色圆；
- 用户能立即知道门锁、空调、摄像机和洗衣机的关键状态；
- 天气和日程只提供“现在和接下来”的信息；
- 复杂设备控制在统一玻璃弹层中完成；
- 详细天气、日历和万年历在 Agenda 中查看；
- 移动端、桌面端和墙屏都保持一致风格；
- 性能不足时一键切换 Lite；
- 页面既有完整毛玻璃质感，又不牺牲可读性、控制准确性和设备安全。
