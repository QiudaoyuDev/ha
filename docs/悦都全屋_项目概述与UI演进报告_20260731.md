## 一、项目概述

本项目是面向**深圳·保利悦都**两室一厅一厨一卫一阳台户型的**家庭智能中控面板**，基于 Home Assistant（HA）原生 Lovelace 构建，主要控制终端为 iPhone，目标体验为"打开像智能家居 App"。

设计哲学（已在 `空间模型规划.md` 与 `docs/Home_Assistant_家庭智能家居_UI方案20260730.md` 中明确）：

- **空间是一级导航，能力是二级组织，设备实体是三级实现**——不把所有设备堆在首页。
- **户型图作为"家庭地图"**，用 2.5D 重绘底图承载空间语义。
- **语义隔离**：底层集成（Xiaomi / Haier）原始状态不直接暴露给家人，统一经模板映射为中文展示态（避免 `unavailable/unknown`）。
- **安全边界**：门锁只展示状态与电量，不暴露远程解锁；摄像机无 `camera.*` 视频流则不提供失效实时画面。

当前已接入实体：主卧空调（`climate`）、主卧循环扇（`fan`）、客厅摄像机开关（`switch`）、入户门锁传感器（`sensor`×3）、阳台洗衣机（`switch`+若干 `sensor`/`select`）。

## 二、核心架构

### 2.1 部署拓扑

```text
[ iPhone / 平板 / 墙面屏 ]
        │  https://host-ip:8123
        ▼
[ Home Assistant 容器 (host 网络) ]  docker compose，ghcr.io/home-assistant/home-assistant:stable
        ├── lovelace (yaml mode) ── dashboard-v2.yaml  (8 个 view)
        ├── template ── templates/yuedu_ui.yaml        (语义展示层)
        ├── script   ── scripts.yaml                    (离家/睡眠模式)
        ├── homekit  ── homekit.yaml                    (Apple Home 桥接)
        ├── custom_components: hacs / xiaomi_home / haier
        └── www/community: lovelace-mushroom / Bubble-Card   (前端卡片)
[ 可选外部服务 ]
        ├── ha-fusion (Hearth) :5050  ── iframe 嵌入的替代前端
        └── micam (Miloco + go2rtc)   ── 摄像机 RTSP 桥接（内网）
```

### 2.2 分层架构

```text
┌─ 表现层 (UI Shell)
│   • 原生 Lovelace（Sections/Panel/Grid 视图）
│   • 2.5D 户型图（picture-elements）
│   • 可选 ha-fusion 独立前端
├─ 语义层 (Semantic)
│   • templates/yuedu_ui.yaml：集成原始态 → 中文展示态 + 离线标记
├─ 控制层 (Logic)
│   • scripts.yaml（离家/睡眠）
│   • HomeKit 桥接（安全子集）
│   • automations.yaml（预留）
├─ 集成层 (Integration)
│   • xiaomi_home（米家设备）
│   • haier（海尔，预留）
│   • hacs（卡片分发）
└─ 基础设施层
    • Docker / host 网络 / TZ=Asia/Shanghai
```

### 2.3 关键设计决策

| 决策 | 说明 | 文件 |
| --- | --- | --- |
| 原生 YAML Dashboard | 稳定、迁移简单，不绑死第三方框架 | `configuration-dashboard-v2.yaml` / `deploy/config/configuration.yaml` |
| 语义模板隔离 | 唯一读取集成原始态的位置，仪表盘只消费中文语义态 | `templates/yuedu_ui.yaml` |
| 2.5D 户型底图 | 重绘正交剖切图，设备状态由实体动态渲染 | `www/floorplan/yuedu-home-2p5d.png` |
| HomeKit 安全桥接 | 仅桥接空调/风扇/摄像机/洗衣机，门锁不暴露 | `homekit.yaml` |
| 多套方案并存 | v2（生产）、lovelace-yuedu（单页旧版）、fusion（iframe 试水） | 三份 yaml |

### 4.3 ⚠️ 文档与实现的矛盾（重要发现）

根目录 `README.md` 声称"**项目使用原生 Lovelace 卡片和 picture-elements，不依赖 HACS**"，但：

- 实际 `dashboard-v2.yaml` 大量使用 `custom:mushroom-template-card`、`custom:mushroom-climate-card`、`custom:mushroom-fan-card`、`custom:mushroom-title-card`、`custom:bubble-card`；
- `deploy/config/configuration.yaml` 明确加载 `hacs`，且 `www/community/` 下存在 `lovelace-mushroom` 与 `Bubble-Card`。

**结论**：生产版 v2 实际上**依赖 HACS 卡片**。"不依赖 HACS"应为早期/目标态描述，需修正文档以免误导部署。建议统一表述为"以原生 Lovelace 为主框架，Mushroom/Bubble Card 作为增强卡片"。

## 五、同类开源项目与 Skill 调研对比

### 5.1 调研对象

- **前端卡片库**：lovelace-mushroom、Bubble Card、Button Card、Tile Card（原生）、card-mod

- **智能体接口（skill 类）**：Home Assistant 官方 MCP 集成、`homeassistant-ai/ha-mcp`、`maximeallanic/homeassistant-mcp`

### 5.2 功能对比矩阵

| 项目 | 类型 | 核心能力 | 与本项目相似点 | 可借鉴点 |
| --- | --- | --- | --- | --- |
| **本项目 v2** | 原生 YAML Dashboard | 空间导航 + 2.5D 户型 + 语义层 | baseline | — |
| **lovelace-mushroom** | 卡片库 | 统一美观实体卡 + 可视化编辑器 + 0 依赖 + Material 配色 + 明/暗主题 | 本项目已采用 | 作为全站卡片风格基准，统一视觉语言 |
| **Bubble Card** | 卡片库 | 底部弹层/弹窗、横向按钮栈、导航锚点触发 | 本项目已采用（状态卡） | 用 Pop-up 实现"就地控制"，替代页面跳转 |
| **Tile Card（原生）** | 原生卡片 | HA 官方统一卡片、状态内容可配 | 旧版 lovelace-yuedu 用过 | 降低对第三方卡片依赖，提升一致性 |
| **card-mod** | CSS 注入 | 对任意 Lovelace 卡片注入 CSS、变量、动画 | 未采用 | 建立设计令牌（design tokens）/主题层 |
| **ha-fusion (Hearth)** | 替代前端 | 独立 App 式 UI、卡片栅格、底部导航、移动优先 | 本项目已 iframe 试水 | 脱离 Lovelace 约束的完整体验，可作 Kiosk/墙屏 |
| **Dwains Dashboard** | 自动生成框架 | 按区域/设备自动布局、多端适配 | 空间模型思想一致 | 设备自动归集逻辑，降低手动维护成本 |
| **Floorplan Card** (chr1st1ank / kishorviswanathan) | 交互户型 | SVG 映射实体、状态着色、点击触发、可视编辑器 | 户型图思想一致 | 比 `picture-elements` 坐标法更易维护、可访问性更好 |
| **Home Assistant MCP** | 智能体接口 | 程序化读/控 HA、被 Claude 等 Agent 调用 | 可作为"AI 管控"扩展 | 让本面板发展为"可对话的家庭中枢"（skill 方向） |

### 5.3 结论

- 本项目在**架构理念（空间模型 + 语义隔离 + 安全边界）**上领先于多数 DIY 方案，且已自研语义层（`yuedu_ui.yaml`）这一差异化能力。
- 在**卡片一致性**与**就地交互（弹窗）**上已引入 Mushroom/Bubble Card，但混用原生 `button`/`entities`/`markdown` 造成视觉语言不统一。
- 在**户型图可维护性**上仍用 `picture-elements` 坐标定位，落后于 Floorplan Card 的 SVG 实体映射方案。
- "Skill"层面可对接 Home Assistant MCP，将面板升级为可由 AI Agent 驱动的家庭中枢。

## 六、UI 层面优化与重构方向

> 目标：符合现代前端 UI 规范（一致性、层级、反馈、可达性、响应式）与交互设计标准（就地操作、状态可见、防错、容错）。

### 6.1 设计系统（Design System）

1. **统一卡片语言**：以 Mushroom 作为全站基准卡片，替换首页中散落的 `type: button`、`type: entities` 普通卡；全屋仅保留"Mushroom + Bubble 弹窗 + 原生 picture-elements/Sections"三类，消除风格分裂。
2. **设计令牌（Design Tokens）**：借助 `card-mod` 定义 CSS 变量（主色、表面色、圆角 `--ha-card-border-radius`、间距、阴影、字体 Inter），形成主题层；暗色模式与 HA 原生主题联动。
3. **空间背景层**：按 `docs/悦都全屋_Home_Assistant_UI优化建议20260730.md` 的 P0 建议，为各空间页增加模糊房间照片/渲染图背景，营造"进入房间"的沉浸感，而非纯设备列表。

### 6.2 布局与层级（Layout & Hierarchy）

4. **采用 Sections 视图**：HA 官方 Sections 提供原生响应式栅格与"水平/垂直堆叠"分区，比手写 `grid`+`vertical-stack` 更易维护、移动端更稳。
5. **信息层级**：首页遵循"家庭状态（聚合）→ 空间入口 → 快捷模式"的视觉优先级；用标题卡、分隔、留白建立节奏，避免当前"卡片平铺 + 大量空白"。
6. **户型图信息增强**：在地图页叠加房间级状态标签（如"主卧 31.3℃ / 空调关闭"），参考 5.2 中 Floorplan Card 的状态着色思路。

### 6.3 交互（Interaction）

7. **就地控制（Pop-up 优先）**：点击设备不再导航到子页，改用 Bubble Card Pop-up 在底部/居中弹层完成控制（空调温度滑杆、风扇挡位、洗衣机程序），符合"操作不离场"的现代交互原则。
8. **状态可见与反馈**：利用语义层已好的中文态，增加**状态驱动配色**（在线绿/离线灰/告警红）与轻量过渡动画（开关态 200ms 缓动），提供操作确认感。
9. **安全防错**：门锁保持只读 + 二次确认；高风险操作（如离家模式关设备）给出明确提示（已有 persistent_notification，可升级为 Bubble 确认弹窗）。

### 6.4 可达性（Accessibility）

10. **触控目标 ≥ 44×44px**、图标配文字标签、保证对比度（WCAG AA），利于 iPhone 单手与墙面屏远距操作。
11. **语义化与朗读**：关键状态用 `aria-label`/可读文本，便于 VoiceOver 与未来语音（HomeKit/Siri）闭环。

### 6.5 响应式与多端

12. **Kiosk / 墙屏模式**：引入 Kiosk Mode 或 ha-fusion 作为固定墙屏前端，隐藏侧栏、常驻家庭地图。
13. **断点适配**：iPhone（单列优先）、平板（双列网格）、桌面（多列）三档布局参数化。

### 6.6 户型图重构（可维护性）

14. **迁移到 Floorplan Card（SVG）**：将 `picture-elements` 的百分比坐标改为 SVG 元素映射，实体与图形解耦，新增设备只需改配置而非重调 `left/top`，且点击热区更精准、可访问性更好。

### 6.7 智能体扩展（Skill 方向）

15. **对接 Home Assistant MCP**：将面板背后的 HA 实例暴露给兼容 MCP 的 AI Agent，使"悦都全屋"从可视化面板升级为"可自然语言管控的家庭中枢"，与现有语义层形成"人看 + AI 管"的双通道。

### 6.8 优先级排序

| 优先级 | 方向 | 预期收益 |
| --- | --- | --- |
| **P0** | 统一卡片语言 + 设计令牌 + 空间背景层 + 修正"不依赖 HACS"文档 | 视觉一致、沉浸感、部署可信 |
| **P1** | Bubble Pop-up 就地控制 + 状态驱动配色/动画 + Sections 视图 + 户型图状态标签 | 交互现代、维护简化 |
| **P2** | Floorplan Card(SVG) 重构 + Kiosk/墙屏 + 响应式断点 + HA MCP 接入 | 可扩展性、多端、AI 化 |

## 七、总结

本项目在**架构理念**上已具备成熟智能家居中控的骨架：空间模型导航、2.5D 家庭地图、语义隔离层、明确的安全边界，并自研了差异化的中文语义展示层。相对同类开源方案（Mushroom/Bubble Card/ha-fusion/Dwains/Floorplan Card），其短板集中在**UI 一致性、就地交互、户型图可维护性**三方面。下一阶段 UI 工作的核心不是增加页面，而是：统一设计语言、用弹窗替代跳转、补强空间沉浸感与状态反馈，并逐步把面板升级为可对接 AI Agent 的家庭数字孪生入口。
