# 悦都全屋空间模型（Dashboard v2）

## 户型解读

户型为两室一厅一厨一卫一阳台，北向在图纸上方。客厅是全屋的交通与公共活动核心：向北连接卧室 A、卫生间、卧室 B，向东连接厨房与入户门，向西连接阳台 A。因此 Dashboard 不把它当成“又一个设备房间”，而是作为安全、可视化和家庭总览的中心。

| 空间 | 图纸关系与职责 | 当前接入能力 | Dashboard 角色 |
| --- | --- | --- | --- |
| 客厅（21.6 ㎡） | 中央公共区，连接各房间 | 摄像机、入户门锁 | 总览安全状态、客厅详情、地图入口 |
| 卧室 A / 主卧（10.0 ㎡） | 客厅西北侧 | 空调、循环扇 | 独立的舒适度控制页 |
| 卧室 B（9.1 ㎡） | 客厅东北侧 | 暂无 | 预留睡眠、灯光、温湿度能力槽位 |
| 厨房（5.5 ㎡） | 客厅东侧 | 暂无 | 预留烹饪、安全、排风能力槽位 |
| 卫生间（3.2 ㎡） | 两卧之间 | 暂无 | 预留照明、排风、湿度能力槽位 |
| 阳台 A（3.6 ㎡） | 客厅西南侧 | 洗衣机 | 独立的洗衣任务页 |
| 入户门 | 客厅东南侧边界 | 门锁传感器 | 安全边界；只读状态和电量，不暴露远程解锁 |

## 架构原则

空间是一级导航，能力是二级组织，设备实体是三级实现。新设备只需加入所属房间的能力卡与地图触点，不改首页结构；尚未接入设备的空间保留入口，避免以后重做导航。

```text
总览（异常 / 正在运行 / 房间入口）
├─ 家庭地图（位置语义与快速详情）
├─ 客厅（安防与可视）
├─ 主卧（环境舒适）
├─ 阳台（洗衣任务）
└─ 次卧 / 厨房 / 卫生间（未来能力槽位）
```

## 户型图触点

`dashboard-v2.yaml` 使用 `www/floorplan/yuedu-home-2p5d.png` 作为生产底图。它以用户提供的户型图为几何参考，重绘为正交 2.5D 剖切视图：墙体、家具、材质和阴影只负责空间识别；设备状态、名称和操作仍由 Home Assistant 实体动态渲染。图纸没有标注真实安装点，当前触点表示**所属空间的控制入口**，并非对设备实际安装位置的断言；安装或迁移后只需微调相应 `left` / `top` 值。

| 触点 | 所属空间 | 位置 | 操作 |
| --- | --- | --- | --- |
| 空调、循环扇 | 主卧 | 西北房间内 | 打开实体详情 |
| 摄像机 | 客厅 | 客厅电视/活动区 | 打开实体详情 |
| 门锁 | 入户门 | 东南入户边界 | 仅查看状态 |
| 洗衣机 | 阳台 A | 西南阳台洗衣位 | 打开实体详情 |

## 实体边界

YAML 只引用现有已确认实体。场景、天气、人员定位、摄像机视频流均不虚构；以后接入时应先在 Home Assistant 形成稳定实体，再添加到相应房间页。门锁由于当前只有传感器实体，保持无解锁动作；摄像机没有 `camera.*` 实体，保持无实时画面卡。
